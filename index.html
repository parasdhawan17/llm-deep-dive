AI, Machine Learning, Deep Learning, Generative AI, and LLMs — the hierarchy

These terms fit inside each other, like boxes inside boxes.

AI is the largest box. Each smaller box is a special case. Most confusion comes from mixing the names.

A 70-year timeline in six steps

  1. 1950s–80s: Symbolic AI. People wrote rules by hand. The rules worked only in narrow tasks.
  2. 1990s–2000s: Statistical ML. Common models: SVMs and decision trees. People designed the features. Models learned the weights.
  3. 2012: Deep learning becomes popular (AlexNet). Networks learn the features themselves.
  4. 2017: "Attention Is All You Need". The Transformer replaces recurrence. It trains in parallel. It scales well.
  5. 2020: GPT-3 shows that scale alone gives new skills. Few-shot learning appears. The era of foundation models starts. A foundation model is a large model trained on broad data. People adapt it to many tasks.
  6. 2022–now: Instruction tuning and RLHF make raw models act as assistants. Open-weight models appear: Llama, DeepSeek, Mistral. You can inspect and run them yourself.

Lesson 1.2

What a language model is — and how it writes answers

A language model predicts the next token. It uses all previous tokens.

A distribution is a set of probabilities. It shows how likely each next token is.

P(tokent+1 | token1 … tokent)

Read it as: the probability of the next token, given all tokens before it.

A 70B model does only this one task when it answers. It is a predictor of the next token. New skills appear from this simple rule. We call this emergent behavior. Emergent behavior is a new ability that appears from simple rules.

Tokens, not words

Models do not read words. They read tokens. A token is a small piece of text. It can be a word or part of a word.

The tokenizer changes text to tokens and back. It uses a fixed list. This list is the vocabulary. A vocabulary has 32,000 to 200,000 entries. Byte Pair Encoding (BPE) is a common algorithm. It builds the vocabulary from text.

Example: "unbelievable" can become ["un", "believ", "able"].

Three facts matter for engineers:

  • Context limits are token limits. 128,000 tokens are about 95,000 English words.
  • Cost is per token. Input and output have different prices.
  • Tokenization explains errors. Models cannot count letters in a word. They never see letters. They see only token pieces.

Generation: the autoregressive loop

The model writes text in a loop. Each step adds one token.

Autoregressive means this: the model uses its own output as new input.

tokens = tokenize(prompt)
while not done:
    logits = model(tokens)            # raw scores for every vocab token
    probs  = softmax(logits / T)       # T = temperature
    next   = sample(probs)             # pick one token
    tokens.append(next)
    if next == EOS or len(tokens) > max_len: done = True
return detokenize(tokens)

The code shows each step. Here is the same loop as actions:

  1. Change the prompt to tokens.
  2. Ask the model for logits. Logits are raw scores. There is one logit for each token.
  3. Change the logits to probabilities. Use softmax and temperature. Softmax is a function. It changes scores to probabilities that sum to 1.
  4. Select one token from the probabilities. This selection is sampling.
  5. Add the token to the sequence.
  6. Stop if the token is EOS or if the sequence is too long. EOS means end of sequence.
  7. If you did not stop, repeat from step 2.
  8. Change the tokens back to text.

The model does not plan a paragraph. Each step uses all previous steps. This gives coherent text.

Decoding: randomness and control

KnobWhat it doesWhen to use it

It gives the model documents to read before it answers. Module 5 describes these fixes.

Lesson 1.3

Transformers and attention — the main mechanism

Before 2017, sequence models were recurrent. RNNs and LSTMs are recurrent models. They read one token at a time. They keep a hidden state. The hidden state is the memory of the model.

They had two large problems. First, no parallel work. Step t waits for step t−1. Second, the vanishing gradient problem. Gradients are the training signals. Over long sequences they become very small. Then learning stops.

The Transformer removed recurrence. The paper is "Attention Is All You Need" (Vaswani et al., 2017). It uses attention instead.

Attention in one paragraph

Attention lets a token see all other tokens. It combines their information with weights. The weights come from learned relevance.

Example: "The animal didn't cross the street because it was too tired". The word "it" must link to "animal". Attention gives a high weight to "animal". It gives a low weight to "street". This selection by content is the main idea.

Self-attention: Q, K, and V

Self-attention is attention inside one sequence. The model changes each token embedding into three vectors. An embedding is a vector. A vector is a list of numbers. It represents the token.

  • Query (Q): what the token requests.
  • Key (K): what the token offers.
  • Value (V): what the token gives if selected.

The relevance of token j to token i is the dot product Q_i · K_j. The dot product measures the match of two vectors. Softmax changes the scores to weights. The weights select the V vectors.

Attention(Q, K, V) = softmax(QKT / √dk) · V

The √d_k term keeps the scores small in large dimensions. Large scores would flatten the softmax. Then the gradients would vanish and learning would stop. This is only matrix multiplication. It runs in parallel for all positions. This parallelism is why Transformers scale. RNNs cannot do this.

Multi-head attention

One attention head learns one type of relation. Example: subject to verb. Multi-head attention runs many heads in parallel. A common number is 32 heads. Each head has its own Q, K, and V. Then the model joins the results.

Heads specialize. Some learn grammar. Some learn links between words. Some learn position patterns. The model handles many aspects at the same time.

Position must be added

Attention does not know order. If you shuffle the tokens, the result is the same. So the model adds position information. A positional encoding is a vector. It tells the position of a token in the sequence.

Early models used fixed waves or learned vectors. Modern LLMs use RoPE. RoPE means Rotary Position Embeddings. It rotates the Q and K vectors by position. It handles long texts better.

The full Transformer block

x = x + MultiHeadAttention(LayerNorm(x))   # communicate between positions
x = x + FeedForward(LayerNorm(x))            # per-position computation (MLP)
# stacked N times (e.g., 32–96 layers); residual connections (+) let
# gradients flow through depth — without them, deep nets don't train.

The block has two main steps. Here they are as actions:

  1. Normalize the input with LayerNorm. LayerNorm keeps the numbers stable.
  2. Run multi-head attention. Add the input back to the output. This is a residual connection. A residual connection adds the input of a layer to its output.
  3. Normalize again with LayerNorm.
  4. Run the feed-forward network. It works on each position alone. Add the input back.
  5. Repeat for all layers. Models use 32 to 96 layers.
  • The feed-forward network holds most parameters. It is a 2-layer MLP. MLP means multi-layer perceptron. It is a small neural network. Modern models often use SwiGLU. SwiGLU is a modern activation function. Most "knowledge" lives here. Attention is the routing.
  • Decoder-only models (GPT, Claude, Llama, DeepSeek) use causal masking. Causal masking stops a token from seeing later tokens. This matches next-token prediction. This is the standard for LLMs.
  • Encoder-only models (BERT) read in both directions. They are good for classification and for embeddings. They cannot generate text.
  • Encoder-decoder models (T5) read the input in both directions. Then they generate the output. They were common for translation. They are rare in new LLMs.

Why models behave differently (preview of Module 3)

The Transformer frame is the same. But models act differently. The causes are the data mix, the scale, the tokenizer, small training changes, and post-training. Post-training includes instruction tuning and RLHF.

RLHF means reinforcement learning from human feedback. It trains the model to prefer answers that humans rate highly.

Architecture is about 20 percent of the story. The rest is the training data and the training method.

The three ideas to keep1. Attention routes information in parallel. It uses learned relevance. 2. Many layers with residual connections change this routing into reasoning-like behavior. 3. The decoder-only model trained on next-token prediction is the modern LLM. The rest is support around it.

MODULE 2

Training LLMs

Module 1 showed how a model generates text. This module shows how engineers build the model. You will follow three stages: pretraining, fine-tuning, and preference training.

Lesson 2.1

Pretraining: From Raw Text to a Base Model

Pretraining teaches a model to predict the next token. A token is a piece of text that the model reads. Engineers train on trillions of tokens.

The result is a base model. A base model is a model that predicts likely text. It does not follow instructions yet.

The data pipeline

Good data matters more than clever code. The pipeline has four steps.

  1. Collect text from books, code, and web pages.
  2. Remove spam, ads, and broken pages.
  3. Remove duplicate text.
  4. Convert clean text into tokens.

A web crawl can collect trillions of words. Most of it is low quality. Filters keep only useful text. Duplicate text is harmful because the model learns to repeat it.

The training loop

Training repeats one small loop billions of times. Each pass through the loop is a training step. A training step updates the model once.

Each step trains on a batch. A batch is a group of token sequences.

for step in range(total_steps):
    batch = get_next_batch(data)      # a group of token sequences
    guess = model.forward(batch)      # forward pass: predict next tokens
    loss = measure_error(guess, batch) # loss: a number for the error
    model.update(loss)                # backpropagation + optimizer step

The forward pass makes predictions. The loss measures the error. Loss is a number that measures prediction error.

Backpropagation is a method that traces error back to each weight. A weight is a number inside the model.

The optimizer then changes each weight by a small amount. An optimizer is a tool that updates weights. Adam is the most common optimizer.

Why training needs thousands of GPUs

A GPU is a chip that does fast math. One GPU is far too slow for pretraining. Engineers split the work across thousands of GPUs.

  • Data parallelism: each GPU trains on a different batch.
  • Model parallelism: the model itself is split across GPUs.

Training can run for many weeks. The cost can reach tens of millions of dollars. This is why only a few labs train frontier models. A frontier model is a model at the edge of current ability.

Note: Pretraining gives knowledge. Later stages shape behavior. Do not expect a base model to act like an assistant.

Lesson 2.2

Scaling Laws: Predictable Gains From Scale

Scaling laws describe how loss falls with more resources. The pattern is smooth and predictable.

In 2020, Kaplan and others found a simple rule. Loss falls in a straight line on a log scale. This holds when you increase compute, data, or parameters. A parameter is a weight that the model learns.

You can predict the final loss before training ends. This helps labs plan large training runs.

The Chinchilla correction

In 2022, the Chinchilla study corrected the recipe. Earlier models used too many parameters and too few tokens. The new rule is simple: use about 20 tokens per parameter.

tokens ≈ 20 × parameters
Model sizeTokens needed (about)
7B parameters140B tokens
70B parameters1.4T tokens
400B parameters8T tokens

For a fixed budget, balance model size and data size. A small model with more data often beats a large model with little data. Overtraining a tiny model also wastes money, so use the rule as a guide.

Note: Scaling laws predict loss, not usefulness. A lower loss usually means a better model, but you must still test on real tasks.

Lesson 2.3

Supervised Fine-Tuning: From Predictor to Assistant

A base model predicts likely text. It does not follow instructions. Supervised fine-tuning (SFT) changes that. SFT trains the model on chosen examples.

Each example pairs an instruction with a good response. Instruction tuning is SFT with instruction examples. The dataset is small: thousands of examples, not trillions.

Why a little good data changes so much

The model already knows facts from pretraining. SFT teaches style and behavior. It learns to answer directly. It learns to refuse unsafe requests. It learns a helpful tone.

Quality beats size here. A few thousand excellent examples can shift behavior strongly. Poor examples teach poor habits.

The SFT procedure

  1. Collect instruction and response pairs.
  2. Check each pair for quality.
  3. Train the base model on the pairs with a small learning rate.
  4. Test the model on new instructions.

Engineers use a small learning rate. A learning rate is the size of each weight update. Small updates protect the knowledge from pretraining.

Note: SFT adds little new knowledge. New facts come from pretraining. SFT mainly changes how the model uses what it knows.

Hints1. The input is an instruction; the target is a good response. 2. It shapes behavior, not knowledge. 3. The example data likely had poor quality or poor tone.

Lesson 2.4

RLHF, RLAIF, and DPO: Learning From Preferences

SFT teaches the format of a good answer. It does not teach which answer humans prefer. Preference training fills this gap.

RLHF in four steps

RLHF means reinforcement learning from human feedback. The method has four steps.

  1. Show humans two answers to one prompt.
  2. Record which answer each human prefers.
  3. Train a reward model on these choices.
  4. Update the language model to earn high reward scores.

A reward model is a model that scores answer quality. PPO then updates the language model in small safe steps. PPO is an algorithm that limits each update size.

RLAIF: AI judges instead of humans

RLAIF means reinforcement learning from AI feedback. A strong AI model ranks the answers instead of humans. AI judges cost less and work faster. Human judges still give better quality for hard cases.

DPO: a simpler path

DPO means direct preference optimization. DPO trains directly on human choices. It needs no reward model. It needs no PPO. This makes DPO simple and stable. Many open models use DPO.

Note: RLHF can make models too agreeable. A model may please the user instead of giving a true answer. Sycophancy means excessive agreement.

Check your understanding

  1. What data does a reward model learn from?
  2. How does RLAIF differ from RLHF?
  3. Why might a team choose DPO over RLHF?
Hints1. Human rankings of answer pairs. 2. An AI judge replaces human judges. 3. DPO is simpler; it skips the reward model and PPO.

MODULE 3

Why Models Behave Differently

GPT, Claude, Gemini, and DeepSeek all use Transformers. Yet they feel different. This module shows why. You will see architecture choices, data choices, and tuning choices.

Lesson 3.1

Architecture Choices: Dense, MoE, GQA, and MLA

Most models share the decoder-only Transformer from Module 1. Labs then change parts of it. Each change balances cost, speed, and quality.

Dense vs mixture of experts

A dense model uses all its weights for every token. MoE means mixture of experts. An MoE model holds many small networks called experts. A router sends each token to a few experts. A router is a small network that picks experts.

Only the chosen experts do work. The model gains large capacity at low cost per token. DeepSeek uses MoE in its large models. Training a router is harder than training a dense model.

GQA: cheaper attention memory

GQA means grouped-query attention. Normal attention gives each head its own keys and values. GQA shares keys and values across groups of heads. This shrinks the KV cache. The KV cache stores keys and values of past tokens. A smaller cache allows longer context and faster generation.

MLA: compressed attention memory

MLA means multi-head latent attention. Latent means hidden and compressed. MLA compresses keys and values into one small vector per token. The model rebuilds what it needs during attention. DeepSeek introduced MLA in its V2 model. It also targets a smaller KV cache.

TechniqueWhat it changesMain effect
DenseUses all weights per tokenSimple; high cost at large size
MoERouter picks a few experts per tokenLarge capacity; lower cost per token
GQAHeads share keys and valuesSmaller KV cache; faster generation

Note: Architecture is only part of the story. Data and post-training often matter more than these tricks.

Lesson 3.2

Data Mix and Post-Training Recipes

Labs train on different data mixes. A data mix is the blend of text types in training. The mix shapes skills directly.

  • More code data improves coding skill.
  • More math data improves math skill.
  • More dialogue data improves chat skill.

Post-training recipes also differ per lab. One lab may favor short answers. Another lab may favor long explanations. One lab may tune for safe refusals. Another may tune for maximum helpfulness.

System prompts shape personality

A system prompt is a hidden instruction from the lab. It sets tone, rules, and limits. It can set the knowledge cutoff date. The knowledge cutoff is the date of the newest training data. You never see this prompt, but you feel its effects.

Note: Two models can share an architecture and still feel different. Data mix, tuning recipe, and system prompt explain most of the gap.

Lesson 3.3

How to Compare Models in Practice

Public scores help, but they can mislead. A benchmark is a fixed test with scores. Models can see benchmark data during training. This inflates scores without real skill gain.

What actually drives the differences you feel

Tool use means the model can call external tools.

  • Knowledge cutoff: fresh facts need fresh data.
  • Context length: long documents need long context.
  • Reasoning effort: hard tasks need more thinking tokens.
  • Tool use: agents need to call search, code, and APIs.
  • Cost and speed: production needs both.

A simple comparison procedure

  1. List your real tasks.
  2. Build a small test set from real examples.
  3. Run each model with temperature 0.
  4. Score the answers yourself.
  5. Compare quality, cost, and speed together.

Your own test beats any public leaderboard. It measures what you actually need.

Note: Do not pick the biggest model by default. A smaller, cheaper model often wins on your task. Test before you commit.

MODULE 4

Choosing a Model

This module teaches you how to choose a model for your task. You will learn what benchmarks can and cannot tell you. You will learn how to test models on your own real work. You will learn how to balance cost, speed, and quality.

Lesson 4.1

Benchmarks and their limits

A benchmark is a standard test. It measures one skill of a model.

Tests you will see

  • MMLU tests school knowledge. It uses multiple-choice questions. It covers subjects like math, history, and law.
  • HumanEval tests code writing. The model reads an English description. It then writes a short program.
  • Other tests measure math word problems, logical reasoning, or chat quality.

Why a high score can mislead you

Your task is not the test. Real inputs are messy and unclear. Test questions are clean and short. A model can win the test and still fail your task.

  • The test style differs from your work.
  • Your users write unclear prompts.
  • Your data has private terms the test never saw.
BenchmarkWhat it measuresIts limit
MMLUSchool knowledge, multiple choiceReal tasks are not multiple choice
HumanEvalShort code from descriptionsReal code needs large context
Chat testsHuman preference votesVotes favor long, confident answers

Contamination and gaming

Contamination means the test questions were in the training data. The model then repeats memorized answers. The score looks high. The true skill is lower.

Gaming means training for the test itself. Builders tune prompts and data for one benchmark. The score rises. Real quality does not rise.

Note: A high score proves skill on that test only. Test the model on your own task before you decide.

Lesson 4.2

Evaluate on your own workload

An eval set is a small group of real examples from your work. Each example has an input and the correct answer.

Build the eval set in six steps

  1. Collect 50 to 200 real inputs from your users.
  2. Write the correct answer for each input.
  3. Run every candidate model on the same inputs.
  4. Score each answer as correct or wrong.
  5. Measure speed and cost for each model.
  6. Choose the model with the best balance for you.

What to measure

quality = correct answers / total answers
cost per 1,000 tasks = tokens per task x price per token x 1,000

Human review or LLM-as-judge

An LLM-as-judge is a strong model that grades answers. Human review is slow. It is the most trusted method. Use it for final decisions. LLM-as-judge is fast. It can favor answers in its own style. Use it for quick first checks.

Note: Test all models with temperature 0. This removes random change. Your comparison stays fair.

Lesson 4.3

Cost, latency, and quality trade-offs

You cannot have the best of all three. You must choose your balance.

Token prices

You pay for each token you send. You pay for each token the model writes. Output tokens usually cost more than input tokens. Long answers cost more than short answers.

Speed

Speed means tokens per second. Small models usually write faster than large models. First-token delay also matters for chat.

When a small model wins

  • The task is simple, for example text labels or short summaries.
  • You run millions of tasks and cost matters.
  • Users need answers in under one second.

When you need a frontier model

A frontier model is the strongest public model of its time.

  • The task needs hard reasoning or long documents.
  • A wrong answer costs you money or trust.
  • The task needs rare knowledge the small model lacks.
Your needBest choice
Simple repeated tasksSmall model
Hard reasoningFrontier model
Tight budgetSmall model
High cost of errorFrontier model
Note: Start with a small model. Move to a larger model only when your tests prove you need it.

MODULE 5

Optimizing for Real Applications

This module teaches you how to improve results in real applications. You will learn prompt design and RAG. You will learn tools, agents, and fine-tuning. You will learn how to make inference cheaper and faster.

Lesson 5.1

Prompt design and RAG

A prompt is the text you send to the model. Good prompts act like programs. They control what the model does.

Three parts of a strong prompt

  1. Role. A role tells the model its job. Example: "You are a bank support agent. Answer in short, polite sentences."
  2. Instructions. Instructions are clear steps. Write them as a short numbered list. Put the most important rule first.
  3. Examples. Examples show input and output pairs. Two or three examples are usually enough. This is called few-shot prompting.

RAG in seven steps

RAG means retrieval-augmented generation. The model reads parts of your documents before it answers.

An embedding is a list of numbers. It shows the meaning of a text. Texts with close meanings have close numbers. A vector store is a database for embeddings.

  1. Split your documents into small chunks of 300 to 800 tokens.
  2. Convert each chunk into an embedding.
  3. Store all embeddings in a vector store.
  4. Convert the user question into an embedding.
  5. Find the chunks with the closest meaning.
  6. Add the top chunks to the prompt.
  7. Send the prompt to the model.
chunks = split(documents)
store.add(embed(chunks))
top = store.search(embed(question), k=5)
answer = model(prompt + top)

When RAG helps and when it does not

SituationUse RAG?
Answers need private company dataYes
Facts change oftenYes
You must cite sourcesYes
The model already knows the factsNo
The task needs pure reasoningNo
Simple open chatNo
Note: RAG grounds the model in your data. It does not fix weak reasoning. Choose a strong model for hard reasoning.

Lesson 5.2

Tools, agents, and fine-tuning

Tool use in six steps

A tool is your code that the model can call. Function calling is the name for this skill.

  1. Describe each tool: its name and its inputs.
  2. The model reads the user request.
  3. The model chooses a tool and gives input values.
  4. Your code runs the tool.
  5. You send the tool result back to the model.
  6. The model writes the final answer.

Agents

An agent is a model that works in a loop. It plans, acts with tools, and observes results. It repeats these steps until the task is done.

while task not done:
    plan = model.think(state)
    result = tools.run(plan.action)
    state.update(result)

Fine-tuning vs RAG

Fine-tuning is extra training on your examples. It changes the model weights.

Your needBest choice
The model must know new factsRAG
Answers must follow your styleFine-tuning
You must show sourcesRAG
You have thousands of example pairsFine-tuning
Your budget is smallRAG
You need both facts and styleUse both
Note: Use RAG for knowledge. Use fine-tuning for behavior. Many strong systems use both together.

Lesson 5.3

Inference optimization

Inference is the act of running the model to make answers.

Quantization

Quantization stores each weight with fewer bits. Fewer bits mean less memory.

FormatBits per weightMemory vs FP32Quality
FP3232FullBest
FP1616HalfAlmost best
INT88QuarterSmall loss
INT44EighthClear loss on hard tasks

Most teams use FP16 or INT8 for good balance.

KV-cache

The KV-cache stores past attention values. The model reuses them for each new token. This makes long answers much faster. It uses extra memory.

Speculative decoding

A small model writes a draft answer. The large model checks the draft. Correct parts stay. Wrong parts get fixed. This is faster than the large model alone.

MethodWhat it savesWhat it costs
QuantizationMemorySome quality
KV-cacheTimeMemory
Speculative decodingTimeAn extra small model
Note: Measure quality after each change. Speed means nothing if answers get worse.

Lesson 6.1

Open weights vs API models

Open weights means you can download the model files. You run them on your own computers. An API model runs on the provider's computers. You send requests over the internet.

Open-weight examples are Llama, DeepSeek, and Mistral. API examples are GPT, Claude, and Gemini.

Licenses

The license tells you what you may do. Some licenses are fully open. Some licenses limit commercial use. Read the license before you use the model.

Lesson 6.2

Run models yourself

VRAM is memory on the graphics card. Model weights live in VRAM during use.

memory = parameters x bytes per parameter

For example, a widely used 8-billion-parameter model in INT4 needs about 4 to 5 GB.

Formats

  • GGUF is a format for CPU use.
  • AWQ and GPTQ are formats for GPU use.
  • All three shrink the model with quantization.

Tools

  • Ollama runs models on your laptop with one command. It is the simplest start.
  • vLLM serves many users at high speed. Use it for production APIs.

Five steps to your first local run

  1. Choose a model and a format for your hardware.
  2. Check VRAM with the math above.
  3. Install Ollama or vLLM.
  4. Download the model files.
  5. Test with a simple prompt.
Note: Start on CPU with a small GGUF model. Move to GPU only when you need more speed.
