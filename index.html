AI & LLM Fundamentals

Lesson 1.1

AI, ML, Deep Learning, Generative AI, LLMs — the real hierarchy

These terms nest inside each other like Russian dolls. Most confusion in the industry comes from using them interchangeably.

TermWhat it actually meansExample
Artificial IntelligenceAny system that performs tasks normally requiring human intelligence — reasoning, perception, language, planning. Includes non-learning systems.Chess engines, rule-based chatbots, A* pathfinding
Machine LearningAI where behavior is learned from data rather than hand-coded: fit a function f(x) → y by minimizing error on examples.Spam filters, credit scoring, recommendation rankers
Deep LearningML using multi-layer neural networks that learn hierarchical representations (edges → shapes → objects; characters → words → concepts).Image classifiers, speech recognition
Generative AIDeep learning models that learn a data distribution and sample new items from it, rather than classifying inputs.LLMs, diffusion image models, voice synthesis
LLMsGenerative models over language: giant Transformers trained on text that model P(next token | previous tokens).GPT, Claude, Gemini, DeepSeek, Llama

The one-sentence discriminator

  • Classical ML predicts a label for an input (discriminative).
  • Generative AI produces new data that looks like its training distribution (generative).
  • An LLM is "just" a generative model whose data is text — and text turns out to encode reasoning, code, facts, and style, which is why the same mechanism does so many jobs.
Mental modelThink of it as specialization layers: AI is the field, ML the dominant method, deep learning the dominant architecture family, generative AI the dominant task shape since ~2020, and LLMs the dominant generative model class. When someone says "AI" today they usually mean LLMs — now you know exactly how much that collapses.

A 70-year timeline in 6 beats

  1. 1950s–80s: symbolic AI — hand-written rules and logic. Brittle outside narrow domains.
  2. 1990s–2000s: statistical ML — SVMs, decision trees; humans engineer features, models learn weights.
  3. 2012: deep learning goes mainstream (AlexNet) — networks learn the features themselves.
  4. 2017: "Attention Is All You Need" — the Transformer replaces recurrence; parallelizable, scalable.
  5. 2020: GPT-3 shows scale alone unlocks few-shot behavior — the "foundation model" era begins.
  6. 2022–now: instruction tuning + RLHF turn raw predictors into assistants; open-weight models (Llama, DeepSeek, Mistral) make the stack inspectable and self-hostable.

Lesson 1.2

What a language model is — and how it generates responses

A language model is a probability distribution over sequences of tokens. Given everything so far, it scores how likely each possible next token is:

P(tokent+1 | token1 … tokent)

That's the entire core. A 70B-parameter model is, at inference time, an extremely sophisticated next-token guesser. Everything impressive — reasoning, code, translation — is emergent behavior of predicting the next token well, at scale.

Tokens, not words

Models don't see characters or words; they see tokens — chunks from a fixed vocabulary (typically 32k–200k entries) learned by algorithms like BPE. "unbelievable" might be ["un", "believ", "able"]. Consequences engineers must internalize:

  • Context limits are token limits (128k tokens ≈ ~95k English words).
  • Cost is per token — input and output priced separately.
  • Tokenization explains quirks: why models fumble at counting letters ("how many r's in strawberry?") — they never saw letters, only token chunks.

Generation: the autoregressive loop

To produce text, the model runs a loop — this is worth visualizing as code, because it demystifies "thinking":

tokens = tokenize(prompt)
while not done:
    logits = model(tokens)            # raw scores for every vocab token
    probs  = softmax(logits / T)       # T = temperature
    next   = sample(probs)             # pick one token
    tokens.append(next)
    if next == EOS or len(tokens) > max_len: done = True
return detokenize(tokens)

Each new token is appended and fed back in — hence autoregressive. The model never "plans" a paragraph; coherence emerges because each step conditions on all previous steps.

Decoding: where the randomness (and control) lives

KnobWhat it doesWhen to use it
temperatureSharpens (T→0, deterministic) or flattens (T→1+, creative/random) the distribution.T≈0 for code, extraction, evals; 0.7–1.0 for brainstorming, writing.
top_p (nucleus)Samples from the smallest set of tokens covering p of probability mass.0.9–0.95 general default; lower for focus.

Why the same prompt gives different answersSampling is stochastic by design. Same prompt + T > 0 → different token draws → different continuations. This is a feature (diversity) and the reason evals and production pipelines pin T=0 + seeds when determinism matters.
Key limitation to carry forwardA base LM predicts likely text, not true text. Fluency ≠ factuality. Hallucination isn't a bug in the mechanism — it's the mechanism operating without grounding. Fixes (RAG, tool use, verification) all live outside this loop; Module 5 covers them.

Lesson 1.3

Transformers & attention — the engine room

Before 2017, sequence models were recurrent (RNNs/LSTMs): they processed tokens one at a time, carrying a hidden state. Two fatal problems: no parallelism (step t waits for t−1) and vanishing gradients over long distances. The Transformer ("Attention Is All You Need", Vaswani et al., 2017) deleted recurrence entirely and replaced it with attention.

Attention in one paragraph

When processing a token, attention lets it look at every other token and pull in a weighted blend of their information — weights decided by learned relevance. In "The animal didn't cross the street because it was too tired", attention lets "it" strongly weight "animal" over "street". That dynamic, content-based routing is the whole trick.

Self-attention, concretely: Q, K, V

Each token's embedding is projected into three vectors:

  • Query (Q) — "what am I looking for?"
  • Key (K) — "what do I contain / advertise?"
  • Value (V) — "what do I actually contribute if selected?"

Relevance of token j to token i = dot product Q_i · K_j. Normalize with softmax, use as weights over V:

Attention(Q, K, V) = softmax(QKT / √dk) · V

The √d_k scaling keeps dot products from exploding in high dimensions (which would saturate softmax and kill gradients). That's the entire operation — matrix multiplies, fully parallelizable across all positions. This parallelizability is why Transformers scale and RNNs didn't.

Multi-head attention

One attention head learns one type of relationship (e.g., subject→verb). A layer runs h heads in parallel (e.g., 32), each with its own Q/K/V projections, then concatenates. Different heads specialize: syntax, coreference, positional patterns. Think of it as the model attending to many linguistic aspects simultaneously.

Position has to be injected

Attention is permutation-invariant — shuffle the tokens, get the same result. So order is added explicitly via positional encodings: original sinusoidal vectors, learned embeddings, and in modern LLMs RoPE (Rotary Position Embeddings), which bakes relative position into the Q/K rotations and extrapolates better to long contexts.

The full Transformer block

x = x + MultiHeadAttention(LayerNorm(x))   # communicate between positions
x = x + FeedForward(LayerNorm(x))            # per-position computation (MLP)
# stacked N times (e.g., 32–96 layers); residual connections (+) let
# gradients flow through depth — without them, deep nets don't train.
  • The feed-forward network (2-layer MLP, often SwiGLU in modern models) holds most of the parameters — it's where "knowledge" largely lives; attention is the routing.
  • Decoder-only (GPT, Claude, Llama, DeepSeek): causal masking — each token attends only to earlier tokens. This is the LLM standard because it matches the autoregressive objective exactly.
  • Encoder-only (BERT): bidirectional attention; great for classification/embeddings, can't generate.
  • Encoder-decoder (T5): reads input bidirectionally, generates output — classic for translation, rarer in frontier LLMs today.

Why behavior differs between models (preview of Module 3)

Same Transformer skeleton, different outcomes — because of data mix, scale, tokenizer, training objective tweaks, and post-training (instruction tuning, RLHF). Architecture is ~20% of the story; the rest is what it ate and how it was raised. You'll be able to say this precisely after Modules 2–3.

The three ideas to keep1. Attention = differentiable, parallel information routing by learned relevance. 2. Depth + residuals + scale convert that routing into reasoning-like behavior. 3. The decoder-only Transformer trained on next-token prediction is the modern LLM — everything else is scaffolding around it.
