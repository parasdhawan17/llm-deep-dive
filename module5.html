MODULE 5

Optimizing for Real Applications

This module teaches you how to improve results in real applications. You will learn prompt design and RAG. You will learn tools, agents, and fine-tuning. You will learn how to make inference cheaper and faster.

Lesson 5.1

Prompt design and RAG

A prompt is the text you send to the model. Good prompts act like programs. They control what the model does.

Three parts of a strong prompt

  1. Role. A role tells the model its job. Example: "You are a bank support agent. Answer in short, polite sentences."
  2. Instructions. Instructions are clear steps. Write them as a short numbered list. Put the most important rule first.
  3. Examples. Examples show input and output pairs. Two or three examples are usually enough. This is called few-shot prompting.

RAG in seven steps

RAG means retrieval-augmented generation. The model reads parts of your documents before it answers.

An embedding is a list of numbers. It shows the meaning of a text. Texts with close meanings have close numbers. A vector store is a database for embeddings.

  1. Split your documents into small chunks of 300 to 800 tokens.
  2. Convert each chunk into an embedding.
  3. Store all embeddings in a vector store.
  4. Convert the user question into an embedding.
  5. Find the chunks with the closest meaning.
  6. Add the top chunks to the prompt.
  7. Send the prompt to the model.
chunks = split(documents)
store.add(embed(chunks))
top = store.search(embed(question), k=5)
answer = model(prompt + top)

When RAG helps and when it does not

SituationUse RAG?
Answers need private company dataYes
Facts change oftenYes
You must cite sourcesYes
The model already knows the factsNo
The task needs pure reasoningNo
Simple open chatNo
Note: RAG grounds the model in your data. It does not fix weak reasoning. Choose a strong model for hard reasoning.

Lesson 5.2

Tools, agents, and fine-tuning

Tool use in six steps

A tool is your code that the model can call. Function calling is the name for this skill.

  1. Describe each tool: its name and its inputs.
  2. The model reads the user request.
  3. The model chooses a tool and gives input values.
  4. Your code runs the tool.
  5. You send the tool result back to the model.
  6. The model writes the final answer.

Agents

An agent is a model that works in a loop. It plans, acts with tools, and observes results. It repeats these steps until the task is done.

while task not done:
    plan = model.think(state)
    result = tools.run(plan.action)
    state.update(result)

Fine-tuning vs RAG

Fine-tuning is extra training on your examples. It changes the model weights.

Your needBest choice
The model must know new factsRAG
Answers must follow your styleFine-tuning
You must show sourcesRAG
You have thousands of example pairsFine-tuning
Your budget is smallRAG
You need both facts and styleUse both
Note: Use RAG for knowledge. Use fine-tuning for behavior. Many strong systems use both together.

Lesson 5.3

Inference optimization

Inference is the act of running the model to make answers.

Quantization

Quantization stores each weight with fewer bits. Fewer bits mean less memory.

FormatBits per weightMemory vs FP32Quality
FP3232FullBest
FP1616HalfAlmost best
INT88QuarterSmall loss
INT44EighthClear loss on hard tasks

Most teams use FP16 or INT8 for good balance.

KV-cache

The KV-cache stores past attention values. The model reuses them for each new token. This makes long answers much faster. It uses extra memory.

Speculative decoding

A small model writes a draft answer. The large model checks the draft. Correct parts stay. Wrong parts get fixed. This is faster than the large model alone.

MethodWhat it savesWhat it costs
QuantizationMemorySome quality
KV-cacheTimeMemory
Speculative decodingTimeAn extra small model
Note: Measure quality after each change. Speed means nothing if answers get worse.
